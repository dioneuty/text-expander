# Feature Specification: 영문 전용 안내 및 확장 모드 선택

**Feature Branch**: `002-english-expansion-mode`

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "한글입력 관련 문구 제거, 영문입력만 가능하도록 안내문 수정. 변환 시 영문키 입력하자마자 변환 혹은 특정 (스페이스 키) 등을 눌러야 변환으로 옵션 추가하기"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 영문 전용 안내로 혼란 제거 (Priority: P1)

사용자는 프로그램을 처음 열었을 때 **한글 입력·IME 관련 안내가 보이지 않고**, 트리거는 **영문(및 숫자·기호)으로만 등록·사용**한다는 안내를 명확히 확인할 수 있어야 한다.

**Why this priority**: 한글 트리거를 지원하지 않는다면 한글 관련 문구는 오해를 유발한다. 사용자가 기대치를 바로잡는 것이 다른 기능의 전제다.

**Independent Test**: GUI와 도움말(README 등 사용자 대면 문서)에서 한글 IME·한글 트리거 관련 문구가 제거되었고, 영문 전용 안내가 표시되는지만 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 메인 화면을 연다, **When** 안내 영역을 확인한다, **Then** 한글 IME·한글 트리거 지원 관련 문구가 표시되지 않는다.
2. **Given** 사용자가 단축어 추가 화면을 연다, **When** 트리거 입력 안내를 확인한다, **Then** 트리거는 영문·숫자·일반 기호 등 **영문 입력 기준**으로 등록·사용해야 한다는 안내가 표시된다.
3. **Given** 사용자가 README 또는 프로그램 내 도움말을 본다, **When** 입력 지원 범위를 확인한다, **Then** 한글 트리거 입력은 지원 범위 밖임이 명시되어 있다.

---

### User Story 2 - 즉시 확장 모드 (Priority: P1)

사용자는 확장 모드를 **「마지막 영문 키 입력 직후 즉시 변환」**으로 선택했을 때, 등록된 영문 트리거의 마지막 글자를 입력하는 순간 별도 키 없이 확장 문장으로 치환되기를 기대한다.

**Why this priority**: 빠른 입력을 원하는 사용자의 핵심 사용 패턴이다. 트리거 완성과 동시에 결과가 나와야 생산성 이점이 크다.

**Independent Test**: `addr` 트리거 하나를 등록하고 즉시 확장 모드로 설정한 뒤, 메모장에서 `addr` 입력만으로(스페이스 없이) 치환되는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 트리거 `myemail`과 확장 문장이 등록되고 확장 모드가 **즉시 확장**이며 서비스가 켜져 있음, **When** 메모장에서 `myemail`의 마지막 글자 `l`까지 입력함, **Then** 스페이스·엔터 등 추가 입력 없이 확장 문장으로 치환된다.
2. **Given** 즉시 확장 모드이고 트리거 `addr`가 등록됨, **When** `add`까지만 입력함, **Then** 치환되지 않고 입력만 유지된다.
3. **Given** 즉시 확장 모드이고 더 긴 트리거 `myaddr`와 짧은 트리거 `addr`가 모두 등록됨, **When** `myaddr`를 완전히 입력함, **Then** **최장 일치** 규칙에 따라 `myaddr`에 대한 확장이 실행된다.

---

### User Story 3 - 키 입력 후 확장 모드 (Priority: P1)

사용자는 확장 모드를 **「지정 키를 눌러야 변환」**으로 선택했을 때, 트리거를 모두 입력한 뒤 **스페이스(또는 설정한 확장 키)** 를 눌러야만 확장되기를 기대한다. 트리거 입력만으로는 치환되지 않아야 한다.

**Why this priority**: 일반 영단어와 트리거가 겹칠 때 오치환을 줄이는 대표적인 완화 수단이다. 즉시 확장과 대비되는 핵심 옵션이다.

**Independent Test**: `addr` 트리거를 등록하고 키 입력 후 확장 모드(기본 확장 키: 스페이스)로 설정한 뒤, `addr`만 입력 시 미치환·스페이스 입력 시 치환을 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 트리거 `addr`가 등록되고 확장 모드가 **키 입력 후 확장**(확장 키: 스페이스)이며 서비스가 켜져 있음, **When** 메모장에서 `addr`만 입력함, **Then** 치환되지 않는다.
2. **Given** 위와 동일한 설정, **When** `addr` 입력 후 스페이스를 누름, **Then** 등록된 확장 문장으로 치환되고, 스페이스는 확장 결과의 일부로 중복 입력되지 않는다(트리거만 치환).
3. **Given** 확장 키로 스페이스 외 **엔터** 또는 **탭**을 선택할 수 있음, **When** 사용자가 엔터를 확장 키로 설정하고 트리거 입력 후 엔터를 누름, **Then** 의도한 확장이 실행된다.

---

### User Story 4 - 확장 모드 설정 저장 (Priority: P2)

사용자는 선택한 확장 모드(즉시 / 키 입력 후)와 확장 키 설정을 변경한 뒤 프로그램을 종료했다가 다시 실행해도 **동일한 설정이 유지**되기를 기대한다.

**Why this priority**: 매번 모드를 다시 고르게 하면 사용성이 떨어진다. 개인 선호는 영속 설정으로 다루는 것이 자연스럽다.

**Independent Test**: 모드를 변경·저장 후 프로그램 재시작 → 이전 모드가 UI와 실제 확장 동작 모두에 반영되는지 확인.

**Acceptance Scenarios**:

1. **Given** 사용자가 **키 입력 후 확장** 모드로 변경하고 저장함, **When** 프로그램을 재시작함, **Then** GUI에 동일 모드가 선택되어 있고 실제 확장 동작도 키 입력 후에만 발생한다.
2. **Given** 사용자가 **즉시 확장** 모드로 변경함, **When** 재시작 후 동일 트리거를 입력함, **Then** 즉시 확장 동작이 유지된다.

---

### Edge Cases

- **영문이 아닌 입력(한글 등)**: 트리거 매칭 버퍼에 반영되지 않으며, 한글 관련 안내 없이도 사용자 입력이 해당 앱에 정상 전달되어야 한다.
- **확장 서비스 OFF/일시 중지**: 어떤 확장 모드든 치환이 발생하지 않아야 한다.
- **짧은 영문 트리거**: 오치환 위험은 기존과 같으며, 즉시 확장 모드에서는 더 주의가 필요함 — GUI 안내에 모드별 주의 문구를 포함한다.
- **확장 모드 전환 직후**: 저장·적용 전까지는 이전 모드가 유지되거나, 저장 시점부터 새 모드가 즉시 반영되어야 한다(일관된 동작 하나로 정의).
- **키 입력 후 확장 모드에서 확장 키 없이 트리거만 입력**: 치환 없음.
- **즉시 확장 모드에서 트리거가 다른 단어의 접두사인 경우**: 트리거 완성 시점에만 확장; 이후 추가 입력 시 새 버퍼 상태에 따라 재판정.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자 대면 안내·도움말·README에서 **한글 입력·한글 IME·한글 트리거 지원** 관련 문구를 MUST 제거한다.
- **FR-002**: 시스템은 트리거 등록·사용 안내에 **영문(라틴 알파벳)·숫자·일반 기호 기준 입력만 지원**한다는 내용을 MUST 표시한다.
- **FR-003**: 사용자는 확장 모드를 **즉시 확장**과 **키 입력 후 확장** 중 하나로 MUST 선택할 수 있어야 한다.
- **FR-004**: **즉시 확장** 모드에서 시스템은 등록된 영문 트리거의 **마지막 문자 입력 직후**, 별도 확장 키 없이 MUST 치환한다.
- **FR-005**: **키 입력 후 확장** 모드에서 시스템은 사용자가 **설정한 확장 키**(최소 스페이스; 엔터·탭 선택 가능)를 누를 때만 MUST 치환한다.
- **FR-006**: **키 입력 후 확장** 모드에서 트리거 문자만 입력된 상태에서는 MUST 치환하지 않는다.
- **FR-007**: 시스템은 기존 **suffix 완전 일치·최장 트리거 우선** 매칭 규칙을 두 확장 모드 모두에 MUST 동일 적용한다.
- **FR-008**: 시스템은 선택한 확장 모드 및 확장 키 설정을 MUST 영속 저장하고, 재시작 후 MUST 복원한다.
- **FR-009**: 시스템은 영문이 아닌 문자(예: 한글)를 트리거 매칭에 사용하지 MUST NOT 한다.
- **FR-010**: 확장 모드 안내는 **즉시 확장 시 오치환 위험이 높을 수 있음**을 사용자가 이해할 수 있도록 MUST 포함한다.
- **FR-011**: GUI에서 확장 모드 변경 시 사용자가 현재 선택을 확인하고 저장할 수 MUST 있다.

### Key Entities

- **ExpansionMode**: 사용자가 선택하는 확장 방식. 값: `immediate`(즉시 확장) | `on_key`(키 입력 후 확장).
- **ExpansionKey**: `on_key` 모드에서 치환을 실행하는 키. 값: `space` | `enter` | `tab` (1차 범위).
- **UserSettings**: 확장 모드·확장 키 등 사용자 환경 설정. 프로그램 재시작 후에도 유지.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: GUI·README·프로그램 내 안내 문구 검토 시 한글 IME·한글 트리거 관련 문구 **0건** 남음.
- **SC-002**: 영문 전용 안내 문구가 메인 화면과 트리거 등록 화면 **각 1곳 이상**에 표시됨.
- **SC-003**: 즉시 확장 모드에서 등록된 영문 트리거 5건 수동 테스트 시 **5/5** 마지막 키 입력 직후 치환 성공(스페이스 불필요).
- **SC-004**: 키 입력 후 확장 모드(스페이스)에서 동일 5건 테스트 시, 트리거만 입력 시 **0/5** 치환, 스페이스 입력 시 **5/5** 치환.
- **SC-005**: 설정 변경 후 프로그램 재시작 3회 반복 시 확장 모드·확장 키 설정 **3/3** 일치.
- **SC-006**: 한글 입력 10회 시도 시 트리거 매칭으로 인한 오치환 **0회**.

## Assumptions

- 본 기능은 한글 트리거·IME 지원을 **제품 범위에서 제외**하고, 사용자 안내와 동작을 **영문 입력 중심**으로 정렬한다.
- 확장 **결과** 텍스트는 한글·여러 줄을 포함할 수 있다(트리거만 영문 입력 기준).
- 1차 확장 키 선택지는 **스페이스·엔터·탭**이며, 사용자 정의 임의 키 바인딩은 범위 밖이다.
- 기본 확장 모드는 **키 입력 후 확장(스페이스)** 로 둔다 — 오치환 위험이 낮고 기존 사용자 기대와 가깝다.
- 기존에 한글 트리거로 등록된 데이터가 있다면, 매칭되지 않을 수 있음 — GUI 영문 전용 안내로 대응(자동 삭제는 1차 범위 밖).
- 확장 서비스 ON/OFF, CRUD, JSON 단축어 저장 등 기존 핵심 기능은 유지한다.

## Compatibility & Scope Boundaries

| 유지 | 변경 |
|------|------|
| 전역 텍스트 확장 | 한글 트리거·IME 관련 사용자 안내 제거 |
| 자유 트리거(접두사 없음) | 영문 입력 기준 트리거 매칭 |
| suffix + 최장 일치 | 확장 모드 2종(즉시 / 키 입력 후) |
| GUI CRUD·서비스 ON/OFF | 설정 영속화(확장 모드·확장 키) |

### Out of Scope

- 한글·IME 기반 트리거 입력 지원
- 사용자 임의 키(예: `;`, `F2`)를 확장 키로 지정
- 확장 모드별 트리거별 개별 설정(전역 설정만)
- macOS / Linux
