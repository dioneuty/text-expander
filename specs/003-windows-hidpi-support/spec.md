## User Scenarios & Testing *(mandatory)*

### User Story 1 - 고배율 화면에서 메인 화면 가독성 (Priority: P1)

Windows 디스플레이 배율이 **125%, 150%, 200%** 등으로 설정된 사용자는 프로그램을 실행했을 때 메인 창의 **글자·버튼·목록**이 흐리거나 지나치게 작지 않고, 일반적인 데스크톱 앱과 비슷한 크기로 읽고 조작할 수 있어야 한다.

**Why this priority**: 메인 화면이 사용 불가능하면 단축어 관리·서비스 ON/OFF 등 핵심 기능에 접근할 수 없다. HiDPI 환경에서 가장 먼저 체감되는 문제다.

**Independent Test**: Windows 배율을 150%로 설정한 뒤 프로그램을 실행하고, 메인 창의 안내 문구·단축어 목록·하단 버튼·설정 영역이 읽기·클릭 가능한지만 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** Windows 디스플레이 배율이 **150%**이고 프로그램을 처음 실행함, **When** 메인 창을 연다, **Then** 안내 문구·목록 헤더·버튼 라벨이 **눈으로 읽을 수 있는 크기**로 표시되고 흐릿하게 보이지 않는다.
2. **Given** Windows 디스플레이 배율이 **200%**임, **When** 메인 창이 **배율에 맞게 확대된 기본 크기**로 표시됨, **Then** 단축어 목록·추가/수정/삭제 버튼·확장 모드 설정·서비스 ON/OFF 영역이 **잘리지 않고** 한 화면에서 확인 가능하다.
3. **Given** Windows 디스플레이 배율이 **100%**(기본)임, **When** 프로그램을 실행함, **Then** 기존과 동일하게 정상 표시되며 레이아웃이 깨지지 않는다.

---

### User Story 2 - 단축어 추가·수정 대화상자 사용성 (Priority: P1)

사용자는 고배율 환경에서 **단축어 추가·수정 대화상자**를 열었을 때 트리거 입력란, 확장 텍스트 영역, 저장·취소 버튼이 **겹치거나 잘리지 않고** 정상적으로 입력·저장할 수 있어야 한다.

**Why this priority**: CRUD는 프로그램의 핵심 작업 흐름이다. 대화상자만 작거나 깨지면 HiDPI 지원이 불완전하다.

**Independent Test**: 배율 150% 이상에서 추가 대화상자를 열고, 모든 필드와 버튼이 보이며 저장까지 완료할 수 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 디스플레이 배율 **150%**에서 메인 창이 열려 있음, **When** 「추가」 버튼으로 대화상자를 연다, **Then** 대화상자가 **배율에 맞게 확대된 크기**로 열리고, 트리거·확장 텍스트 입력 영역과 안내 문구, 저장·취소 버튼이 **모두 보이고** 클릭·입력 가능하다.
2. **Given** 동일 환경에서 기존 단축어를 선택함, **When** 「수정」 대화상자를 연다, **Then** 기존 값이 표시되고 필드·버튼 레이아웃이 깨지지 않는다.
3. **Given** 배율 **200%**에서 대화상자를 연다, **When** 긴 확장 텍스트를 입력함, **Then** 텍스트 영역 스크롤로 전체 내용을 확인·편집할 수 있다.

---

### User Story 3 - 배포 실행 파일에서 동일한 표시 품질 (Priority: P2)

사용자는 **소스에서 직접 실행**할 때와 **빌드된 Windows 실행 파일(.exe)** 로 실행할 때 **동일한 HiDPI 표시 품질**을 기대한다. exe만 흐리거나 작게 보이면 안 된다.

**Why this priority**: 실사용·배포 경로는 exe가 많다. 개발 실행만 선명하면 사용자 문제가 남는다.

**Independent Test**: 동일 PC·동일 배율에서 `python main.py`와 빌드 exe를 각각 실행해 시각적 차이가 없는지 비교.

**Acceptance Scenarios**:

1. **Given** 디스플레이 배율 **150%**인 PC, **When** 소스 실행과 exe 실행을 각각 함, **Then** 메인 창·대화상자의 **글자 크기·선명도·레이아웃**이 실질적으로 동일하다.
2. **Given** exe만 배포받은 사용자, **When** 고배율 노트북에서 실행함, **Then** Windows 호환성/흐림 문제 없이 일반 앱 수준으로 표시된다.

---

### User Story 4 - 혼합 DPI 모니터 환경 (Priority: P3, best-effort)

**서로 다른 배율**을 사용하는 모니터가 연결된 환경에서, 프로그램 창을 다른 모니터로 옮겼을 때 **즉시 완벽한 표시**를 보장하지는 않지만, **재시작 후** 해당 모니터 배율에 맞게 정상 표시되면 1차 릴리스 기준을 충족한다.

**Why this priority**: 노트북+외부 모니터 조합이 흔하나, 1차 목표는 **단일 모니터 고배율(125/150/200%)** 이다. 혼합 DPI 실시간 대응은 구현·검증 비용 대비 우선순위가 낮다.

**Independent Test**: 주 모니터 150%, 보조 100% 구성에서 (1) 단일 모니터에서 정상 표시 확인, (2) 창 이동 → 재시작 후 보조 모니터에서 정상 표시 확인.

**Acceptance Scenarios**:

1. **Given** 주 모니터 150%에서 프로그램을 실행함, **When** 메인 창·대화상자를 사용함, **Then** P1/P2 시나리오와 동일하게 **읽기·조작 가능**하다.
2. **Given** 실행 중 창을 보조(100%) 모니터로 이동함, **When** 표시가 어색해질 수 있음, **Then** 프로그램 **재시작 후** 보조 모니터에서 FR-001~FR-003을 충족하면 1차 릴리스 **통과**로 본다.
3. **Given** 창이 보조 모니터에 있고 재시작 후 정상 표시됨, **When** 단축어 추가 대화상자를 연다, **Then** 대화상자도 **잘리지 않고** 사용 가능하다.

---

### Edge Cases

- **배율 125%**: 100%와 150% 사이의 중간 배율에서도 UI가 정상 표시되어야 한다.
- **225% 이상 고배율**: 흔한 범위(125~200%) 우선; 극고배율에서는 최소한 텍스트·버튼이 식별 가능해야 한다.
- **실행 중 배율 변경·모니터 이동**: Windows 설정 배율 변경 또는 **혼합 DPI 모니터 간 창 이동** 직후에는 재시작 전까지 완벽 반영이 어려울 수 있음 — **재시작 후 정상**이면 1차 릴리스 허용.
- **전역 키보드 확장 동작**: HiDPI는 **GUI 표시**에 한정하며, 메모장 등 다른 앱에서의 텍스트 확장 동작은 변경하지 않는다.
- **최소 창 크기**: 사용자가 창을 과도하게 줄였을 때 일부 잘림은 허용; **기본 창 크기**에서는 잘리지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 프로그램은 Windows 시스템 디스플레이 배율(**100%, 125%, 150%, 200%**)에 맞춰 GUI 요소가 **선명하고 적절한 크기**로 표시되어야 한다.
- **FR-002**: 메인 창의 안내 문구, 단축어 목록, CRUD 버튼, 확장 모드 설정, 서비스 ON/OFF 영역은 **기본 창 크기**에서 잘리거나 겹치지 않아야 한다.
- **FR-007**: 프로그램 기본 창 크기는 **100% 배율 기준 720×540**을 기준으로 하며, Windows 디스플레이 배율이 높아지면 **동일 비율로 기본 창 크기를 확대**해야 한다(예: 150% → 약 1080×810).
- **FR-003**: 단축어 추가·수정 대화상자의 모든 입력 필드, 안내 문구, 저장·취소 버튼은 FR-001의 배율에서 **완전히 보이고 조작 가능**해야 한다.
- **FR-009**: 단축어 추가·수정 대화상자는 **100% 배율 기준 레이아웃 크기**를 기준으로, FR-007과 **동일한 DPI 배율 규칙**으로 기본 크기·내부 여백·입력 영역을 확대해야 한다.
- **FR-004**: PyInstaller 등으로 빌드한 **Windows 실행 파일**도 소스 실행과 **동등한 HiDPI 표시 품질**을 제공해야 한다.
- **FR-005**: HiDPI 개선은 **GUI 표시·레이아웃**에만 적용하며, 단축어 등록·전역 확장·설정 저장 등 **기존 기능 동작은 변경하지 않는다**.
- **FR-006**: 100% 배율(기존 환경)에서 **회귀 없이** 현재와 동일하거나 개선된 표시를 유지해야 한다.
- **FR-008**: **단일 모니터** 125/150/200% 배율이 1차 릴리스 **필수 검증** 대상이며, **혼합 DPI 모니터** 환경은 best-effort로 **재시작 후 정상**이면 통과한다.

### Key Entities

- **표시 배율 컨텍스트**: 사용자 PC의 Windows 디스플레이 배율(100~200% 등) 및 연결된 모니터 구성. 프로그램이 이를 인지해 UI 크기·선명도를 맞춘다.
- **GUI 화면**: 메인 창, 단축어 추가·수정 대화상자 — HiDPI 지원의 적용 대상.
- **배포 실행 파일**: end-user가 실행하는 `.exe` — 소스 실행과 동일한 HiDPI 기대치를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 배율 **150%** 환경에서, 수동 검사 시 메인 창의 **모든 주요 UI 요소**(안내·목록·버튼·설정·서비스 토글)가 **읽기·클릭 가능**하다고 테스터 1명이 확인할 수 있다.
- **SC-002**: 배율 **200%** 환경에서, **배율에 맞게 확대된 기본 창 크기** 기준 **수평 스크롤 없이** 메인 화면 핵심 영역이 표시된다.
- **SC-003**: 배율 **150%** 이상에서 **배율에 맞게 확대된** 단축어 추가 대화상자로 **저장까지** 3분 이내에 완료할 수 있다(레이아웃 문제로 인한 추가 조작 없이).
- **SC-004**: 동일 PC·동일 배율에서 소스 실행과 exe 실행의 **시각적 차이**가 수동 비교 시 **눈에 띄지 않는다**.
- **SC-005**: 배율 **100%** 환경에서 기존 사용자 시나리오(목록 조회, 추가, 서비스 ON/OFF)가 **회귀 없이** 동작한다.

## Assumptions

- 대상 OS는 **Windows 10/11**이며, macOS/Linux HiDPI는 범위 밖이다.
- 사용자는 Windows **시스템 디스플레이 배율**을 사용하며, 프로그램 내부 **별도 배율 슬라이더**는 1차 범위에 포함하지 않는다.
- HiDPI 적용 범위는 **tkinter GUI**(메인 창·대화상자)이며, 전역 키보드 후킹·JSON 저장·확장 모드 로직은 변경하지 않는다.
- Windows 설정 **배율 변경** 또는 **혼합 DPI 모니터 간 창 이동** 후에는 **프로그램 재시작**으로 정상 표시를 확인한다(실시간 Per-Monitor DPI 추적은 1차 범위 밖).
- 검증 우선 배율: **125%, 150%, 200%** — 업무용 노트북·4K 모니터에서 흔한 값.
- 기본 창 크기는 **100% 배율 기준 720×540**(최소 560×420)이며, 고배율에서는 **동일 비율로 기본 창을 확대**한다. 단축어 추가·수정 대화상자도 **동일 DPI 배율 규칙**을 적용한다. 사용자가 창 크기를 수동 조절한 경우는 그 설정을 우선한다.

## Compatibility & Scope Boundaries

### In Scope

- 메인 창 및 단축어 추가·수정 대화상자의 **가독성·선명도·레이아웃**
- Windows **100~200%** 단일 모니터 사용성(필수)
- 혼합 DPI 모니터: **재시작 후 정상**이면 통과(best-effort)
- **exe 빌드** 결과물의 HiDPI 일관성

### Out of Scope

- macOS/Linux HiDPI
- 사용자 정의 UI 배율 설정 UI
- 실행 중 실시간 DPI 변경·모니터 이동 즉시 반영(재시작 후 정상이면 1차 허용)
- 트레이 아이콘·OS 알림 등 아직 미구현 UI
- 전역 텍스트 확장(키보드 후킹) 동작 변경

### Regression Guard

- 단축어 CRUD, `settings.json` 확장 모드, 즉시/키입력 후 확장, 영문 트리거 규칙 등 **002-english-expansion-mode**에서 확정된 동작은 유지한다.
